Getting started

Alexandria keeps one library for one person, gathered from several sources. Each source keeps its own notebooks and devices, because each one syncs in its own way. Search, tasks and handwriting recognition work across all of them.

To add content, connect a device from Add source. Notebooks appear after the device's first sync.

Alexandria Client

The Alexandria Client app syncs notebooks and books with this server using its own protocol. Recognized handwriting can sync back to Client devices, so the text shows up there too.

Book dates: Created is when the Client first recorded the book, not its publication date. Modified includes title and annotation changes.

{{if $d.NativeBOOX}}

BOOX

BOOX tablets connect through the PowerSync app, which points the tablet's built-in Notes and NeoReader sync at this server instead of Onyx's cloud. Your notebooks keep their native format, and every tablet signed in to the same BOOX account shares one library.

Browsing is read-only. Opening notebooks or pages here never changes your tablets. Only a few actions write back: deleting numbered notebooks, uploading a book, refreshing reading data and audio recovery. Each of those says so before you confirm.

Page previews are drawn on the server from the ink files received so far. Pen textures are approximate. A missing preview does not mean the page is blank; some files may still be on their way.

When two tablets disagree, Alexandria follows the same winner the tablets' own sync chooses. Every version the server sees is kept, so earlier versions can be recovered, but changes a tablet never sent can't be recovered.

Reading shows books, highlights and bookmarks from NeoReader. Page numbers are shown exactly as the tablet recorded them. You can upload EPUB or PDF books (up to 64 MiB); each tablet downloads a book when you open it in its library.

Going back to Onyx: use Restore in PowerSync on the tablet. Revoking a device here only removes its access to this server; it does not switch the tablet back.

{{end}}

Devices

Each source keeps its own device list. A tablet connected through two sources appears in both.

Alexandria Client devices
Sign in from the Client app's Settings → Sync using this server's address and your account. Waiting counts changes the device has not pulled yet. Clear sync position is safe for a device still in use; it picks up where it left off.
{{if $d.NativeBOOX}}
BOOX devices
Install PowerSync, enter this server's address, and type a one-time code from Connect a device. Codes expire after ten minutes. Authorized means a tablet may connect; it doesn't mean everything has finished downloading.
{{end}}
Revoking
Stops a device syncing. Its notes stay in your library.

Search

Search looks through Alexandria Client page text and book annotations{{if $d.NativeBOOX}}, BOOX notebook titles, book titles, highlights and notes, and handwriting from BOOX pages that have been recognized{{end}}. Pages that have never been recognized can only be found by title, so if a search misses something, check whether its pages have been through recognition.

Words and meaning (shown when search by meaning is on) also finds related ideas. Exact words only matches what you typed. Use the source menu to narrow results to one source.

Search by meaning

Semantic search turns your text into vectors so a search for “budget” can find a page about “cost showback”. It needs an embedding provider: the optional bundled Ollama service runs the Nomic model on the server's CPU, or you can point it at another Ollama-compatible endpoint.

Settings shows three separate things, because each can be true without the others:

Provider
Whether the saved embedding service answers. Checked without sending any of your notes.
Semantic search
Whether you've turned the feature on.
Index
Whether the vectors exist yet. Building takes a while; the previous index stays usable until a replacement finishes.

Turning it off keeps the index and pauses new work, so turning it back on resumes quickly. Search by meaning only indexes text that already exists. It never starts handwriting recognition.

Handwriting recognition

Recognition sends page images to a vision model you configure and stores the text it returns, which makes the pages searchable. It can cost money, so nothing is sent until you confirm.

Providers
Anthropic Messages or OpenAI Chat Completions formats, including local OpenAI-compatible servers such as vLLM. API keys are encrypted in the database and never displayed after saving.
Where text goes
Alexandria Client text can sync back to Client devices.{{if $d.NativeBOOX}} BOOX text stays on this server: it's searchable here but never changes your BOOX notebooks.{{end}}
One notebook or a whole library
Recognize individual pages from a notebook, or use Recognize a library. A library run first checks every notebook's page list. That check is free and doesn't contact your provider. You then review and exclude notebooks before confirming. Pages are sent in chunks of up to 100.
Pause, cancel and retry
Pausing or cancelling stops results being published, but a request already sent may still finish and be billed. Resuming may send it again. Retry reuses unchanged successful results. Temporary failures retry automatically up to five times.
Image size
Each page is sent as a JPEG of at most 1 MB and 4096 pixels on its long side. Pages are never enlarged. Base64 encoding adds about a third to the request size.
Reprocessing
Re-runs pages that were already recognized or requested, using the current settings. Unchanged pages reuse cached results; a new model or prompt can cost money again.
Connection tests
Send a synthetic image or sentence, never your notes. They may cost a fraction of a cent and don't save settings.

Audio Note Minutes

Audio Note Minutes summarize a BOOX note from its recordings and its handwriting. Talk Insights on the device only hears the audio; here, what you wrote down counts as much as what was said.

What you get
The overall topic, 4–6 keywords, up to five key points (each marked as coming from the recording, your notes or both) and a conclusion. Each note also lists its recordings with start time and length, and the full timestamped transcripts.
How it works
Open a notebook and choose Summarize this note…. You'll see the recordings and how many pages have recognized text before anything is sent. Each recording is transcribed, then a summary model writes the minutes.
Pages without text
You can include unrecognized pages; they're sent to your recognition provider first (charges may apply) and the minutes wait for them. Otherwise they're left out and listed.
Providers
Set up in Settings → Recognition under Audio Note Minutes. Transcription uses any OpenAI-compatible speech-to-text server, including a self-hosted Whisper. The summary model can be a local OpenAI-compatible server or an Anthropic model.
Keeping up to date
Minutes are marked out of date when a recording or recognized page changes. Updating is always your choice; unchanged recordings aren't transcribed again.
Where results go
They stay on this server, appear in search and are available to MCP clients through get_note_minutes. Nothing is written to your BOOX until you choose Send to BOOX, which creates a separate text note named title_Minutes in the same folder. Your original notebook is never changed. Sending again replaces that note if it's untouched; if you've edited it, a new one is added instead. To send every new set of minutes automatically, turn on Send them to BOOX automatically in Settings → Recognition.
{{end}}

Deleting and recovering

Alexandria Client notebooks
Devices delete the notebook on their next sync. If a device edits it afterwards, it comes back.
{{if $d.NativeBOOX}}
BOOX numbered-notebook cleanup
BOOX names new notebooks Notebook-1, Notebook-2 and so on. Cleanup finds notebooks named exactly that, across folders, so you can delete the ones you never renamed. It matches names only and doesn't look at the pages, so open anything you're unsure about. Deletion syncs to every BOOX tablet using this library.
Deleted BOOX notebooks
Stay viewable under Deleted notebooks. The server keeps their history and files, so deletion doesn't free storage space.
{{end}}
Tasks
Deleted tasks go to a separate list first.

Tasks and CalDAV

Tasks is one list across your library. Tasks made from Alexandria Client pages link back to their page.{{if $d.NativeBOOX}} BOOX task extraction is not available yet.{{end}}

Any CalDAV task app can sync the list using the address in Settings → Tasks & integrations and your account. Choose Date only if your app mishandles due times.

API and MCP access

Claude on the web connects using this server's MCP address. You approve it on a page here, and it then appears in your token list. Other MCP clients and scripts use an API token from Settings → Tasks & integrations. A token can search and read your notebooks and books, edit text boxes and manage tasks, so revoke any you no longer use. A token is shown once, when you create it.

Your account

Passwords need at least 12 characters (up to 72 bytes). After a change your browser may ask you to sign in again. Enrolled devices and API tokens keep working.

Operator notes

  • The footer and the alexandria-version meta tag show the build that's running. The readiness endpoint is /readyz.
  • Every ? button has a data-help key matching the help registry in internal/alexandria/web/help.go. Popover text is in the page HTML even while closed.
  • Each page's <body> carries data-section, and the Settings, Client and BOOX tabs use aria-current="page".

  • BOOX diagnostics lists the raw records the server has observed, with native IDs and revisions. Each record's Observed versions link opens its retained history as JSON from /api/v1/boox/admin/history.
    • {{end}}
  • Recognition job details include the encoded image size and model. Batches and library runs keep their history after they finish.
