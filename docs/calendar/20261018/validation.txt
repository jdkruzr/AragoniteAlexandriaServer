Expansion contract and deliberate limits
- Shared internal read-only projection, no migration or public event API change.
- Ordinary events queried by bounded windows; imported blobs remain candidates
  even when their master DTSTART is old. Calendar, Upcoming and Past share one
  request budget and occurrence expansion.
- At most 10,000 displayed occurrences and 100,000 generated candidates across
  the request. Conservative work estimation can reject a costly sparse rule
  before iteration. Cancellation is checked between records and candidates.
- Uses pinned go-ical and rrule-go 1.8.2. Calendar candidates are generated on a
  floating clock then resolved in the recurrence zone to avoid DST-gap shifting.
- Unsupported cases are visible and name the series: EXRULE, period-valued
  RDATE, unknown/non-IANA TZIDs, multiple/missing masters, multiple RRULEs,
  duplicate overrides, recurrence rules on overrides, non-THISANDFUTURE ranges,
  BYEASTER and filtered subdaily RRULEs. Custom VTIMEZONE definitions are not
  interpreted independently of IANA zones. Original blobs are untouched.
- Selected date stays in navigation URLs, not the landing preference cookie.
  Browsed dates accept years 1900–9998; Upcoming extends in 30-day steps to
  3,660 days, with occurrence limits still applying.
- CSP permits inline style attributes for server-generated numeric grid
  positions; scripts remain local external files and event content is escaped.

Reproducing browser checks
1. Configure disposable integration fixtures as in .github/workflows/ci.yml.
2. Create an empty output directory, then run:
   ALEXANDRIA_CALENDAR_BROWSER=<directory> go test -count=1 \
     -run '^TestCalendarBrowserFixture$' ./internal/alexandria/web
3. Once <directory>/url exists, run:
   ALEXANDRIA_CALENDAR_BROWSER=<directory> node scripts/calendar-browser.cjs
   Install Playwright for the driver or set PLAYWRIGHT_MODULE to its module path.
   The driver uses /usr/bin/google-chrome. It writes a stop sentinel on completion
   so the fixture server exits and testenv drops the synthetic database.
